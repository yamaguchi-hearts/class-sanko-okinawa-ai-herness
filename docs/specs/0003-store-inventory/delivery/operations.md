# 配布・運用

[設計索引](../README.md) / 対応: 原Plan §5.5、§10 Phase 5、§12

## 配布 R-OPS

Windows x64向けNSISを標準とし、ポータブル版は初期版の必須にしない。アプリ識別子、ユーザーデータ保存先、インストール識別の安定性を維持する。依存・lockfile・開発/テスト/ビルドの実コマンドを記録する。初回起動と更新インストールの双方でネイティブSQLite/Argon2idを検証する。

## READMEへ含める利用手順

- 対応OS、単一店舗/PC・オフラインという範囲、対象外。
- 初回ADMINセットアップ、次回ログイン、ロック・ログアウト、自分のパスワード変更。
- ユーザーの追加と一度限りのコード配布、本人による設定、無効化、最後のADMIN保護。
- 商品/カテゴリ、入出庫/棚卸、訂正は追加操作で行うこと、履歴/検索/CSV。
- 商品画像はADMINがPNG/JPEGから選択し、商品ごとに1枚を登録・差替え・削除する。STAFFも閲覧できる。画像はSQLite内にPNG BLOBとして保存され、最大5MiB、各辺4,096px。画像を含むバックアップも暗号化されない。
- 実際のuserData/DB保存場所。更新時のデータ保持と移行前バックアップ。
- バックアップの作成（商品画像を含む）、定期的な別媒体保存、置換確認、復元後の旧パスワードやユーザー構成への戻り、再ログイン。
- 全ADMINがログイン不能な場合のオフライン管理者復旧ツールの起動・昇格・対象確認・事前バックアップ・コード・本人設定。DB破損は既知のバックアップ復元。
- DB直接編集を推奨しないこと、暗号化なし、Windows管理者/直接アクセスに対する限界、Windowsアカウントとディスク保護。
- 通常ログの実保存場所とローテーション設定、問い合わせ時に秘密を含めないこと。

## 通常ログ

監査テーブルと障害解析用のファイルログを分ける。ファイルログは初期案として5MB×5世代でローテーションし、無限増大させない。監査/在庫履歴の自動削除は設けない。ディスク不足時は成功を偽らず、DB変更の原子性を保つ。

## 受け入れ条件

R-OPS-01: クリーンなWindows環境相当でNSISインストール、初期設定、主要業務、終了・再起動、更新、バックアップ復元ができる。

R-OPS-02: 開発環境なしで復旧ツールを利用でき、READMEから別担当者が業務復旧を再現できる。

R-OPS-03: DB非暗号化、別媒体保管、直接編集の制約をアプリとREADMEで説明する。
