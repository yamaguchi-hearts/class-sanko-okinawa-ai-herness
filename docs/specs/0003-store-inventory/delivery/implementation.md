# 実装フェーズ・依存関係

[設計索引](../README.md) / 対応: 原Plan §10、§14

## 作業単位

共有型、正規化、エラー、認可マトリクス、マイグレーションはPhase 0/1で定義元を確定する。複数の実装者がいる場合も同じ共有型や移行ファイルの同時編集を避ける。通常は以下の順序で進め、前段の未検証事項を後段の実装量で覆い隠さない。

| Phase | 実装範囲・成果物 | 前提・完了ゲート | 引き継ぎ |
| --- | --- | --- | --- |
| 0 | Electron骨格、React、Vite、ネイティブSQLite/Argon2id、隔離データ、NSIS試作、依存固定 | Windows開発/パッケージ起動、DB保存・再読込、KDF照合。以後の共有契約と移行の担当を確定 | [Phase 0](../../../prompts/0003-store-inventory/phase-0.md) |
| 1 | DB基盤、app_meta/users/reset/audit/settings、IPC保護、セットアップ、認証/ロック/自分の変更、ユーザー登録/コードフロー | 初回のみセットアップ、次回ログイン、失効・認可、本人の再設定が縦断で動く | [Phase 1](../../../prompts/0003-store-inventory/phase-1.md) |
| 2 | 商品・カテゴリ、一覧/検索、ユーザー管理UI仕上げ、最後のADMIN保護、変更監査 | STAFFの商品管理拒否、重複/無効化/履歴保持、管理画面からのアカウント配布 | [Phase 2](../../../prompts/0003-store-inventory/phase-2.md) |
| 3 | 入出庫/棚卸、movement、低在庫/0在庫、ダッシュボード、履歴 | 唯一の更新経路、負在庫禁止、更新+movement+auditの原子性 | [Phase 3](../../../prompts/0003-store-inventory/phase-3.md) |
| 4 | CSV、設定、バックアップ/復元、保守サービス、オフライン管理者復旧ツール | 式安全化、現DB退避、検証付き復元、失敗時復帰、Windows管理者による本人再設定 | [Phase 4](../../../prompts/0003-store-inventory/phase-4.md) |
| 5 | 横断E2E、NSIS最終化、更新インストール、Windows検証、READMEと運用文書 | 全受け入れ条件、再現可能な開発/テスト/配布、バックアップと復旧手順 | [Phase 5](../../../prompts/0003-store-inventory/phase-5.md) |

原Planではユーザー管理がPhase 1/2へ重複していたため、Phase 1でサービスと最小縦断、Phase 2で管理画面と残る業務ケースを完成させる。管理者復旧ツールは追加要件としてPhase 4に配置する。

## 各フェーズの記録

実装者は変更・検証・制約をREADMEまたは本ディレクトリの判断記録へ残す。未実行、失敗、成功を分けて報告し、対象変更を日本語で自動コミットする。受け入れゲートを満たせない場合は理由を示し、依存する後続を完了扱いしない。
