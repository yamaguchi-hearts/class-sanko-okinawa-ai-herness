# 画面・操作規約

[設計索引](../README.md) / 対応: 原Plan §3.2、§4

## 要求 R-UI

UIとエラーは日本語。日時はDBへUTC ISO 8601で保存し、画面ではWindowsのローカル時刻で表示する。店舗名、画面名、ログイン中の表示名とロールを共通レイアウトへ表示する。

## 画面遷移

| 状態 | 表示・許可する導線 |
| --- | --- |
| 未セットアップ | 店舗名、管理者表示名、ログインID、パスワードと確認欄 |
| セットアップ済み・未認証 | ログイン、再設定コードを使う導線 |
| 認証済み | ダッシュボードを初期表示し、在庫一覧・履歴へ移動可能 |
| ロック中 | 現在ユーザーの再認証、ログアウトのみ |
| 再設定中 | 本人の新パスワード設定、キャンセル・ログアウトのみ |
| 復元処理中 | 処理状態を表示し、業務操作を停止 |

ADMINに限り商品編集、ユーザー管理、カテゴリ管理、設定、バックアップ/復元への導線を示す。商品・カテゴリの参照情報はSTAFFも閲覧可能。認証・ロック・再設定の各画面でも終了・キャンセルができ、セッションがある状態では常にログアウトできる。

## 主要画面

ダッシュボード、在庫一覧、商品作成/編集、在庫変更、商品別/全体在庫履歴、ユーザー管理、カテゴリ管理、設定、バックアップ/復元、自分のパスワード変更を用意する。再設定コードは専用の一時表示と本人入力画面を使う。オフライン管理者復旧は別ツールとする。

## 共通状態と操作

- 空状態、検索結果なし、読込中、入力エラー、処理失敗、再試行を区別する。
- 保存中は二重送信を止め、完了と失敗を表示する。読取は再試行できるが、結果不明の在庫変更・復元等を自動再送しない。
- 無効化、ロール変更、再設定コード発行、復元などの影響を確認画面で示す。
- 復元の確認には対象バックアップと現在データが置き換わる旨、事前バックアップ、再起動が必要な旨を示す。
- フォームのラベル、キーボード操作、フォーカス、入力エラーの対応を設ける。色だけで低在庫・在庫0やエラーを区別しない。
- ロック前の入力は業務画面から隠し、再認証後に再取得する。パスワードとコードの入力は成功・失敗・画面離脱時に消去する。

## 受け入れ条件

R-UI-01: 初回セットアップからダッシュボード、終了後のログイン、ロック・解除の状態遷移をE2Eで確認する。

R-UI-02: STAFFの直接ルート遷移を拒否し、各一覧とフォームで空・読込・失敗状態を区別できる。

R-UI-03: 在庫変更の送信中に操作を連打してもUIから二重送信せず、失敗を成功表示しない。
