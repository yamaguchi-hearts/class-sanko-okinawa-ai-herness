# ユーザー管理・再設定・管理者復旧

[設計索引](../README.md) / 対応: 原Plan §3.1、§12、追加A-02/A-03

## ユーザー管理 F-USERS

ADMINは個人別ユーザーを作成し、表示名・ロールを変更、無効化、再設定要求を発行できる。削除APIは設けない。通常画面へpassword_hashや失敗制御の詳細を返さない。最後の有効ADMINを無効化/STAFFへ降格する操作は、監査を含む書込みトランザクションで再確認して拒否する。

他ユーザーの初期パスワードを管理者が指定する方式は採用しない。新規ユーザーは推測不能なランダム値をArgon2id化した使用不能な初期資格情報と `must_change_password=1`、一度限りの再設定コードを同時作成する。本人がコードから新パスワードを設定するまで業務ログインを許さない。通常のmust-changeユーザーにも、通常パスワードだけで業務セッションを発行しない。

ロール変更・無効化・再設定要求は対象の既存セッションを失効させる。監査には変更前後の非機密情報を残し、過去の在庫履歴の本人ID・表示名スナップショットは変更しない。

## 一度限りの再設定コード F-RESET

1. ADMINが対象ユーザーを確認し、発行の影響を承認する。
2. Mainが暗号学的乱数32バイトからコードを生成する。有効期間は15分、ユーザーごとに1件とし、再発行は旧コード・制限セッションを失効させる。
3. DBには高エントロピーコードのSHA-256ダイジェスト、有効期限、失敗回数、発行者・状態のみ保存する。これはパスワードハッシュの代替ではなく、ランダムな一時コードの照合用である。
4. 平文コードは発行結果として一度だけADMINに表示し、本人へ直接伝える。ログや監査、履歴画面へ出さず、コピーする場合は利用者の明示操作とする。
5. 本人がログインIDとコードを専用画面に入力する。期限、対象有効性、失効/消費状態を検証し、コードをトランザクション内で消費する。業務権限を持たない制限セッションを発行する。
6. 制限セッションの期限は残るコード有効期限までとする。検証済みコードの再利用、別ユーザーへの流用、業務API呼び出しを拒否する。
7. 本人が新パスワードを設定したらArgon2id更新、must-change解除、認証失敗回数・待機解除、全コード/セッション失効、監査を一括確定する。通常ログインへ戻し、新パスワードを要求する。

コード誤入力は対象アカウントの有効コードについてDBで数え、5回で失効させる。未知IDや無効コードも共通エラー・頻度制御とする。コード消費後に画面を閉じた、期限切れになった場合は再発行が必要。通常の自分のパスワード変更は現在パスワード必須であり、このコード認証の別経路だけを例外とする。

## オフライン管理者復旧ツール F-RECOVERY

管理者が初期版への追加を承認した明示的な別ツールとする。通常アプリに秘密のURL、マスターキー、既定アカウントは作らない。Windowsローカル管理者がDBを直接扱えるという既存の境界を前提とし、以下を設計条件とする。

- Windowsの管理者昇格を要求し、昇格済みでない場合は変更しない。別ユーザーとして昇格する場合は対象アプリのuserDataを明示選択し、アプリ種別・インストールID・店舗名を確認する。
- 通常アプリが停止し、同一データ領域の排他ロックを取得できる場合に限る。DB形式、スキーマ、整合性を検証し、先に一貫性のある別ファイルバックアップを作る。
- 既存の有効ADMINを選び、ユーザー・店舗・対象データ・影響を表示して確認する。新規の秘密ADMINを作らず、STAFFを黙って昇格させない。有効ADMINが存在しない異常DBは自動修復せず、既知のバックアップ復元へ進む。
- 確認後は対象ADMINの再設定要求、失敗制御解除、旧コード失効、新しい一度限りのコード発行を同一トランザクションで行う。コードは端末へ一度だけ表示し、引数・環境変数・ファイル・ログに平文を残さない。
- auditに `ADMIN_RECOVERY_REQUESTED` と `actor_kind=OFFLINE_RECOVERY`、対象ユーザーID、Windows実行者識別、退避識別子を記録する。アプリ利用者による操作と偽らない。
- アプリを通常起動し、本人がコードでパスワード設定後、ログインする。復旧ツール自体は業務セッションを発行しない。
- DBが壊れている場合のオフライン復元も、候補検査・既存DB退避・一貫した入替・失敗時復帰・監査を通常復元と共通化する。これはアプリ内のADMIN認可とは別のWindows管理者による保守権限である。

## 受け入れ条件

F-USERS-01: STAFFによるユーザー管理を拒否し、最後のADMINを失う操作を競合時も拒否する。

F-RESET-01: 発行、期限切れ、5回失敗、再発行、消費、再利用拒否、新パスワード設定前の業務拒否をテストする。

F-RESET-02: 新規ユーザーは管理者が本人のパスワードを指定せず利用開始でき、変更後は新パスワードでのみログインできる。

F-RECOVERY-01: Windows上で非昇格・アプリ起動中・別アプリDBを拒否し、正規手順ではバックアップ、監査、コード発行、本人ログインまで確認する。
