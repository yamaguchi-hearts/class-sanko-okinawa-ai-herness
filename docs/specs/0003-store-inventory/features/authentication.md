# 初期設定・認証・セッション

[設計索引](../README.md) / 対応: 原Plan §3.1、§4.1–4.2、§5.3–5.4

## 要求 F-AUTH

初回起動はログインではなくセットアップへ誘導する。店舗名、管理者表示名、ログインID、パスワードと確認入力を受け付ける。Mainでは店舗名・ユーザー・設定・セットアップ済みマーカー・監査を一括保存し、作成したADMINのセッションを開始する。UI確認用パスワードは不一致を検証するが、不要に永続化・監査しない。

既定アカウント・既定パスワード・開発用バックドアを設けない。セットアップAPIは同一トランザクションで未実施か再確認し、二重送信や並行呼び出しで複数の初期管理者を作らない。

原Planの「管理者が存在しない」は新品DBの起動条件として扱う。セットアップ済みマーカーがあるのに有効ADMINが存在しないDBは異常状態とし、セットアップを再開して権限を得られる状態にしない。業務を停止して明示的な復旧を案内する。

## 入力とログイン

- loginNameはtrim+小文字化して保存・検索する。表示名と店舗名はtrim後1〜100文字、ログインIDはtrim後1〜64文字とする。
- 原仕様は12〜128 Unicodeコードポイント。0004の[R-DEMO](../../0004-demo-enhancements/requirements/demo-password.md)適用後は、新規設定を4〜128 Unicodeコードポイントとする。空白やパスフレーズを許し、trim・大文字小文字変換・Unicode正規化をしない。確認欄と完全一致させる。
- Argon2idの保存形式を用い、メモリ/反復/並列度と処理時間をPhase 0で記録する。
- 正常ログインでfailed_login_countとlocked_untilをリセットし、last_login_atと監査を保存する。
- 5回目の連続失敗から30秒、以後の有効な試行失敗ごとに60、120、240、300秒を上限として待機する。待機中の試行で期限を際限なく延長しない。回数と期限は再起動後も維持する。
- 未知ID・無効ユーザーも共通エラーにする。未知IDにはダミーArgon2id検証とMainの共通頻度制御を使い、既知アカウントだけ別の待機情報を返さない。
- 自分の通常パスワード変更には現在パスワードを要求し、更新後は全セッションと再設定コードを失効させてログインへ戻す。

## セッション状態

| 状態 | Mainの保持情報 | 次の状態 |
| --- | --- | --- |
| ANONYMOUS | 業務トークンなし | ログイン/初期セットアップでAUTHENTICATED |
| AUTHENTICATED | 非公開ランダムトークン、本人、webContents、発行・最終操作・期限 | 無操作でLOCKED、ログアウト/変更でANONYMOUS |
| LOCKED | トークン破棄、本人と同じwebContentsのロック文脈 | 本人パスワードで新トークン発行、またはログアウト |
| PASSWORD_RESET_REQUIRED | コード検証済みの制限セッション、本人、元コードID、有効期限 | 新パスワード保存後ANONYMOUS |

業務トークンの有効期限は、Mainの最終本人操作時刻+設定された無操作時間（既定15分、最大60分）とする。実際の本人操作だけが期限を延長し、単なる読取や自動ポーリングは延長しない。操作ごとにトークン自体を入れ替えて並行リクエストを誤失効させる方式は採らず、Mainの単一セッション状態を更新する。Mainタイマーと各IPC実行前の両方で期限を確認し、セッションを維持するだけのハートビートは設けない。

読取の自動ポーリング、非同期処理の完了、モーダルが開いている時間を本人操作に数えない。Preloadは信頼済みのキー/ポインター操作から限定した操作通知を送り、Mainが受信時刻を記録する。Rendererが指定した任意時刻は採用しない。改変済みRendererに対する物理操作の完全証明は対象外。

長時間処理は開始時に認可し、ロック後は新しい保護処理を拒否する。開始済みのトランザクションは安全に完了/失敗させ、ロックを理由に部分保存しない。復元の破壊的適用前など境界を越える時点では認可を再確認する。

## 受け入れ条件

F-AUTH-01: 新品DBのセットアップは一度だけ成功し、再起動するとANONYMOUSになる。

F-AUTH-02: パスワード境界、5回失敗・待機延長・再起動維持・正解後リセットを制御した時計で検証する。

F-AUTH-03: 無操作ロックで旧トークンが使えず、解除には現在本人のパスワードが必要。ポーリングでロックが延期されない。

F-AUTH-04: セットアップ済みで管理者が欠落しても再セットアップで権限を作れず、復旧案内となる。
