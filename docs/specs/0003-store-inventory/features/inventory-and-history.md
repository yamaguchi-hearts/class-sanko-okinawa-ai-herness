# ダッシュボード・在庫一覧・履歴

[設計索引](../README.md) / 対応: 原Plan §3.2、§3.5

## 在庫一覧 F-LIST

商品名、SKU、カテゴリ、現在庫、最低在庫数、単位、有効/無効、低在庫/0在庫の状態を表示する。有効商品を既定とし、無効/全件も選択可能にする。検索・フィルタ変更時は1ページ目へ戻す。

- 検索はtrim後のSKU・商品名の部分一致、大小文字を区別しない。SKUと商品名に同じ検索語をOR適用し、カテゴリ・在庫条件とはANDで組み合わせる。
- `%` と `_` は検索語として文字どおり扱い、LIKEのワイルドカードとして解釈させない。商品名はMainで作成する `name_search_key` と同じtrim+小文字化を検索語へ適用し、SQLite NOCASEだけに依存しない。
- 初期順は商品名昇順、同名時SKU昇順、最後にIDで安定化。日本語の厳密な辞書順までは求めず、使用する照合順を固定してテストする。
- ソートキーは商品名、SKU、現在庫、最低在庫数。許可リストでSQLへ変換する。
- ページは50件が初期値、最大200件。総件数と現在ページを返し、条件一致がなくても正常な空結果とする。

## 在庫状態 F-DASHBOARD

低在庫は `current_stock <= reorder_level && reorder_level > 0`。0在庫は `current_stock === 0`。両者は排他的ではない。最低在庫0・現在庫0は低在庫に含めず、0在庫に含める。定義を共有ドメインに置き、一覧SQLと集計の条件も同じ境界でテストする。

ダッシュボードは登録商品数（無効を含む総数）、有効商品数、低在庫商品数（有効のみ）、在庫0商品数（有効のみ）、直近10件の在庫変更を表示する。集計範囲は設計判断として統一し、画面に明示する。

## 履歴 F-HISTORY

商品別/全体の日時、商品名・SKU、種別、数量差分、before/after、理由、メモ、操作者を表示する。商品ID・期間・種別・実行者IDの組合せで絞り、日時降順・ID降順で安定ページングする。

画面の日付範囲はローカルの開始日0時以上・終了日の翌日0時未満をUTCへ変換する。日付切替やタイムゾーン差による境界をテストする。ユーザー・商品の無効化で過去の履歴を消さない。操作者は保存済みスナップショットを表示する。商品名・SKUは原Planどおり商品IDから現在値を表示し、変更前の商品名称の復元は商品変更監査で追跡する。

在庫履歴画面とアプリ監査ログは別の保存目的であり、監査専用の閲覧UIは初期版に追加しない。

## 受け入れ条件

F-LIST-01: trim・大小文字・日本語検索、文字どおりの`%/_`、複合フィルタ、並び順・ページ境界を検証する。

F-DASHBOARD-01: 在庫0/最低0、在庫0/最低1、在庫=最低、最低超過、無効商品で一覧と集計の判定が一致する。

F-HISTORY-01: 期間のUTC境界・実行者・種別で絞れ、操作者の改名/無効化後も記録時の表示名が残る。
