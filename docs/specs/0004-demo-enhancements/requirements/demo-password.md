# DEMOのパスワード要件

[索引](../README.md) / 要求 R-DEMO / 管理者確定: 最小4文字

## 変更する要件

DEMOでは新しく設定するパスワードを4〜128 Unicodeコードポイントとする。セットアップ、自分の変更、再設定コードからの本人設定、復旧後の本人設定に同じ定数・検証関数を適用する。空白やパスフレーズを許し、文字種の組合せ制約は追加しない。パスワードのtrim・大小文字変換・Unicode正規化は行わない。

ログイン・ロック解除・現在パスワードの照合は、既存と同じ1〜128文字の非空入力を受け付け、保存済みハッシュと照合する。新規設定の最小長を照合APIで再判定しない。既存の12文字以上のパスワードとハッシュは変更せず利用できる。

## 実装上の定義元

`src/shared/validation/` にDEMOポリシーの定数を置き、Mainの各新規設定APIが必ず再検証する。RendererのminLengthだけではUTF-16コード単位とコードポイント数が異なるため、それだけに依存しない。確認欄の完全一致と4/128境界を同じ関数で判定する。

Rendererの説明、placeholder、エラー、セットアップ/変更/再設定の全画面を4文字に統一する。ログイン画面等にDEMO版であることを示し、READMEへ現行ポリシーを記載する。今回はDEMOそのものの下限を変更し、未依頼の本番/DEMO切替や設定APIを追加しない。

## 維持する機能

Argon2idと現在のパラメータ、ソルト付きハッシュ、ログイン、失敗制御、無操作ロック、ADMIN/STAFF認可、再設定コードの一度限り/有効期限、監査の秘密除外は維持する。共通パスワード、認証スキップ、既定アカウントを追加しない。

## 変更対象と旧仕様

- `src/shared/validation/index.ts` のpassword関数は現状12文字固定。4文字へ置換し、重複した条件も統一する。
- `src/main/auth/service.ts`、Rendererの認証フォーム、`tests/unit/database-auth.test.ts`、認証E2Eを確認する。
- 0003の `features/authentication.md` と `delivery/decisions.md` の12文字下限を現行仕様として使用しない。実装時に0004への参照を加える。過去のテスト記録は保持する。
- DB移行は不要。ハッシュ再生成や一括パスワード変更要求も不要。

## 受け入れ条件 AC-DEMO

3文字拒否、4文字成功、128文字成功、129文字拒否、確認不一致、空欄拒否を新規設定の全入口で確認する。絵文字を含むコードポイント境界をテストする。既存の長いパスワードでログインでき、Argon2id/待機/ロック/権限の回帰がない。
