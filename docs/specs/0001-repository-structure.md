# 0001: リポジトリ構成設計

## 状態・参照

- 状態: 初期構成作成済み
- Plan: [0001-repository-structure.md](../plans/0001-repository-structure.md)
- 実装プロンプト: [0001-repository-structure.md](../prompts/0001-repository-structure.md)

役割指示の配置は後続の [0002: 役割別Skill設計](0002-role-skills.md) で更新した。現在の `AGENTS.md` は役割選択と共通規約を担い、詳細な手順は各Skillに保持する。

## 目的と範囲

管理者の要求から設計・実装引き継ぎまでを、会話が変わっても再開できる構成にする。今回は文書と作業規約を整備する。アプリケーションの実装、技術スタックの選定、CI導入は対象外。

## 構成と責務

| 配置 | 責務 |
| --- | --- |
| `AGENTS.md` | 設計者の役割、日本語、質問、引き継ぎ、自動コミットの規約 |
| `README.md` | リポジトリの入口と利用手順 |
| `docs/plans/` | 管理者の要求と出典の保存 |
| `docs/specs/` | Planを具体化した設計と受け入れ条件 |
| `docs/prompts/` | GPT6-Luna［High］への実装指示 |
| `docs/templates/` | 新規設計書・プロンプトの共通ひな型 |

対応するPlan・設計書・プロンプトは4桁IDとslugを一致させ、相互参照する。履歴はGitで保持する。今回のIDは `0001` とする。

## 設計上の判断

- 再利用するエージェント指示はルートの `AGENTS.md` に集約する。
- Planの保存先は設計者が選択した `docs/plans/` とする。これは管理者から指定された配置ではなく、要求の追跡に必要な設計判断である。
- テンプレートは最低限の項目を示し、個別Planに応じてデータ設計やAPI設計などを追加する。
- モデルの指定は引き継ぎ先を示す。モデル・推論設定の実際の選択は実行環境で行う。
- 実装者のプロンプトでは当該作業の実装者ロールを明示し、設計者の通常作業範囲と区別する。

## 不明点・失敗時の扱い

重要な要件の欠落は管理者に質問し、未回答の要件を確定しない。Gitコミットが失敗した場合は変更を保持し、原因を報告する。今回の構成を作成する上での未決事項はない。

## 受け入れ条件と検証

- ルートに再利用可能な `AGENTS.md` と案内用 `README.md` がある。
- 本Plan、設計書、実装プロンプトが対応する配置と名前で存在する。
- 設計書・実装プロンプトのテンプレートがある。
- 文書のローカル参照が解決でき、指示と配置が整合している。
- `git diff --check` が成功し、今回の成果物が日本語のメッセージでコミットされる。

文書のみの変更のため、アプリケーションの動作テストは不要。
