## 共通指示

1. `AGENTS.md`、`.agents/skills/software-implementer/SKILL.md`、[追加Plan](../../plans/0004-demo-enhancements.md)、[設計索引](../../specs/0004-demo-enhancements/README.md)、対象タスクの設計を読む。Skillが使えなくても本書と参照文書で実装できるようにする。
2. 0003の基本設計に0004の差分を適用する。npm、最小12文字、作成時在庫0固定という旧仕様を実装し直さない。画像・初期在庫の変更はADMINだけに許可する。
3. Git状態と最新コードを読み、Phase 4等の進行中の変更を保護する。調査時には多数の未コミット変更があった。同じファイルの変更が衝突する場合は担当者と調整し、他作業をまとめてコミットしない。
4. 既存のMain認証・認可・入力検証・監査を継承する。画像の任意パス、商品編集経由の在庫変更、DEMOを理由にしたログイン迂回を追加しない。
5. 軽微な判断は理由を記録する。技術スタック変更、重要な要件変更、既存データを失う移行が必要なら管理者へ確認し、該当部分は確定まで止める。
6. テストDB/userData/画像/バックアップは専用一時領域を使い、通常の店舗データを使わない。変更に適した既存テストを実行し、必要な動作テストを追加する。
7. 実装後は対応する現行設計・README・検証記録を更新し、新旧仕様の参照をそろえる。過去の実行結果をpnpmで検証済みのように書き換えない。
8. 今回の対象ファイルのみを明示してステージし、日本語で自動コミットする。無変更の空コミット・履歴書換え・無断pushはしない。
9. 変更内容、検証コマンド/結果、未実行/残る課題、コミットID、Git状態を日本語で報告する。
