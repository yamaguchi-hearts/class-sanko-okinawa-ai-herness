# 0003: 店舗向け在庫管理アプリ 実装引き継ぎ

実装者は GPT6-Luna［High］を想定する。モデルと推論設定は実行環境で選択する。各フェーズプロンプトと本書、参照資料だけで新しい会話から着手できるようにしている。

## 共通指示

1. この作業では対象Planの実装者として作業する。`AGENTS.md` と `.agents/skills/software-implementer/SKILL.md` を読む。Skillが使えない環境でも本書の指示に従って実装する。
2. [原Plan](../../plans/0003-store-inventory.md)、[管理者決定](../../plans/0003-store-inventory-decisions.md)、[設計索引](../../specs/0003-store-inventory/README.md) を読む。原Planの要約だけで実装せず、担当機能の設計と共通基盤を確認する。
3. 指定されたPhaseを対象とし、前段の成果と検証結果、Git状態を確認する。前提が欠けていれば依存部分を実装済み扱いしない。ユーザーの未コミット変更を保護する。
4. 原Planの要求と設計判断を区別する。重要な設計変更・要件の矛盾は理由と影響を示して管理者へ確認する。軽微な実装判断と検証結果は `docs/specs/0003-store-inventory/delivery/decisions.md` へ記録する。
5. Mainを認証・認可・DB・ファイル操作の境界とする。Rendererに秘密、汎用IPC、Node/SQLを渡さない。保護APIは発信元・DTO・セッション・現在のロールを検証する。
6. テストは専用の一時DB/userData/出力先で行い、実ユーザーデータを使用/削除しない。存在するnpm scriptsを確認して実行する。Phase 0で必要なscriptsを定義し、以後は実名をREADMEへ記載する。
7. 変更に適したテストと各Phaseのゲートを検証する。失敗を修正し、環境による未実行は理由・影響を記録する。ゲートが未検証ならそのPhaseを完了扱いしない。
8. 必要な文書を更新し、今回のファイルを明示してステージし、日本語で自動コミットする。変更なしなら空コミット不要。無関係な変更を含めず、pushは別途依頼された場合に限る。
9. 日本語で変更内容、実行した検証と結果、未検証/未解決事項、コミットID、Git状態を報告する。コミット失敗を成功扱いしない。
